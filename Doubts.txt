mkdir GitPractical

git init

Experiment 5: Configure a Basic GitHub Actions Workflow to Automatically Display a Build Success Message on Every Push
1. Aim of the Experiment

To learn how to:

Configure GitHub Actions
Create a workflow file
Run automation on every push
Display a success message automatically
2. Theory
What is GitHub Actions?

GitHub Actions is a CI/CD automation tool provided by GitHub.

It helps automate:

Build process
Testing
Deployment
Notifications
3. What is Workflow?

A workflow is an automated process defined using a YAML (.yml) file.

Workflow files are stored inside:

.github/workflows/
4. Workflow Architecture
Push Code → GitHub Actions Triggered → Run Workflow → Show Success Message
5. Step-by-Step Procedure
Step 1: Create Project Folder
mkdir GitHubActionExperiment

Move into folder:

cd GitHubActionExperiment
Step 2: Initialize Git Repository
git init
Step 3: Create a Sample File
notepad demo.txt

Write:

Hello GitHub Actions

Save file.

Step 4: Create GitHub Actions Folder

Run:

mkdir .github
mkdir .github\workflows
Step 5: Create Workflow File

Create file:

notepad .github\workflows\main.yml
Step 6: Add Workflow Code

Paste this code:

name: Build Success Workflow

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Display Success Message
        run: echo "Build Successful!"

Save file.

Experiment 6: Create a Simple CI/CD Workflow Using GitHub Actions to Build and Deploy a Static HTML Page
1. Aim of the Experiment

To learn how to:

Create a static HTML webpage
Configure CI/CD using GitHub Actions
Automatically deploy website using GitHub Pages
2. Theory
What is CI/CD?
CI (Continuous Integration)

Automatically builds and checks code whenever changes are pushed.

CD (Continuous Deployment)

Automatically deploys application after successful build.

3. What is GitHub Pages?

GitHub Pages is a free hosting service provided by GitHub to host static websites.

4. Workflow Architecture
Push Code → GitHub Actions Triggered → Build Website → Deploy to GitHub Pages
5. Step-by-Step Procedure
PART A — Create Project
Step 1: Create Project Folder
mkdir CICDExperiment

Move into folder:

cd CICDExperiment
Step 2: Initialize Git Repository
git init
PART B — Create HTML Page
Step 3: Create HTML File
notepad index.html

Paste this code:

<!DOCTYPE html>
<html>
<head>
    <title>CI/CD Demo</title>
</head>
<body>
    <h1>Welcome to GitHub Actions CI/CD</h1>
    <p>Static website deployed successfully.</p>
</body>
</html>

Save file.

PART C — Create GitHub Actions Workflow
Step 4: Create Workflow Folder
mkdir .github
mkdir .github\workflows
Step 5: Create Workflow File
notepad .github\workflows\deploy.yml
Step 6: Add Workflow Code

Paste this YAML code:

name: Deploy Static Website

on:
  push:
    branches:
      - main

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup GitHub Pages
        uses: actions/configure-pages@v5

      - name: Upload Pages Artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: .

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

Save file.

6. Explanation of Workflow
Section	Purpose
on: push	Runs workflow on every push
checkout	Downloads repository files
configure-pages	Configures GitHub Pages
upload-pages-artifact	Uploads website files
deploy-pages	Deploys website

Step 7: Add Files

Step 9: Create GitHub Repository

notepad .github\workflows\python-test.yml

Experiment 9: Use Docker Compose to Run Two Containers Together Such as a Web Server and Database Service
1. Aim of the Experiment

To learn how to:

Use Docker Compose
Run multiple containers together
Configure web server and database services
Manage multi-container applications
2. Theory
What is Docker Compose?

Docker Compose is a tool used to define and run multi-container Docker applications using a YAML file.

Why Docker Compose?

Instead of running containers one-by-one, Docker Compose can start all services together using a single command.

3. Architecture
Web Server Container  ←→  Database Container
        Nginx                 MySQL
4. Requirements

Install:

Docker Desktop
Docker Compose (comes with Docker Desktop)

Verify installation:

docker --version
docker compose version
5. Step-by-Step Procedure
PART A — Create Project Folder
Step 1: Create Folder
mkdir ComposeExperiment

Move into folder:

cd ComposeExperiment
PART B — Create Web Page
Step 2: Create HTML File
notepad index.html

<head>
    <title>Docker Compose Demo</title>
</head>
<body>
    <h1>Docker Compose Working Successfully!</h1>
    <p>Web server and database containers are running together.</p>
</body>
</html>

Save file.

PART C — Create Docker Compose File
Step 3: Create Compose File
notepad docker-compose.yml

Paste this YAML code:

version: '3'

services:

  web:
    image: nginx:latest
    ports:
      - "8080:80"

    volumes:
      - ./index.html:/usr/share/nginx/html/index.html

  database:
    image: mysql:8.0

    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: testdb

    ports:
      - "3306:3306"

Save file.

6. Explanation of docker-compose.yml

web	Nginx web server

Experiment 10: Write and Execute an Ansible Playbook to Install Apache/Nginx and Start the Service on a Linux Machine
1. Aim of the Experiment

To learn how to:

Install Ansible
Create an Ansible inventory
Write an Ansible playbook
Install Apache/Nginx automatically
Start and enable the web server service
2. Theory
What is Ansible?

Red Hat Ansible is an automation tool used for:

Configuration management
Application deployment
Server automation
What is a Playbook?

An Ansible playbook is a YAML file containing automation tasks.

3. Architecture
Control Node → Managed Linux Machine
      |
      └── Install Apache/Nginx Automatically
4. Requirements

Install:

Linux machine / Ubuntu VM
Ansible
5. Install Ansible

For Ubuntu/Linux:

sudo apt update
sudo apt install ansible -y

Verify installation:

ansible --version
6. Step-by-Step Procedure
PART A — Create Project Folder
Step 1: Create Folder
mkdir AnsibleExperiment

Move into folder:

cd AnsibleExperiment
PART B — Create Inventory File
Step 2: Create Inventory File
nano inventory

Add:

[webservers]
localhost ansible_connection=local

Save file.

Nano Save:
CTRL + O → Enter
CTRL + X
7. Explanation of Inventory
Part	Meaning
[webservers]	Server group
localhost	Current machine
ansible_connection=local	Local execution
PART C — Create Playbook
Step 3: Create Playbook File
nano apache-playbook.yml

Paste this code:

---
- name: Install and Start Apache
  hosts: webservers
  become: yes

  tasks:

    - name: Install Apache
      apt:
        name: apache2
        state: present
        update_cache: yes

    - name: Start Apache Service
      service:
        name: apache2
        state: started
        enabled: yes

Save file.

8. Explanation of Playbook
Section	Purpose
hosts	Target systems
become: yes	Uses sudo
apt	Installs package
service	Starts service
PART D — Execute Playbook
Step 4: Run Playbook
ansible-playbook -i inventory apache-playbook.yml
Expected Output
PLAY RECAP
localhost : ok=2 changed=2 unreachable=0 failed=0
PART E — Verify Apache Service
Step 5: Check Apache Status
sudo systemctl status apache2

You should see:

active (running)
Step 6: Open Browser

Visit:

http://localhost

You will see Apache default webpage.
